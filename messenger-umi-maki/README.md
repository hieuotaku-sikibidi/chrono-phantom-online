# Messenger Umi and Maki

A small, real multi-user chat application. Accounts and friend/message records are stored in PostgreSQL; Socket.IO delivers new direct messages and online presence.

## Features
- Account registration and login with a unique shareable ID such as \`UM-9A01BC2D\`
- Search people by ID, username, or display name
- Incoming and outgoing friend requests, accepting and withdrawing requests
- Edit profile name, bio, and avatar
- Direct messages stored in PostgreSQL and delivered live through Socket.IO
- Empty friend list by default — no seeded or fake friends

## Deployment
The root \`render.yaml\` is configured for Render. Open the repository in Render Blueprints, select branch \`umi-maki-messenger\`, and apply the Blueprint. The web service uses this folder as its root, and \`DATABASE_URL\` is linked to the \`umi-maki-db\` PostgreSQL resource. \`JWT_SECRET\` is generated by Render.

The free Render PostgreSQL plan shown in this setup expires after 30 days. Use a non-expiring paid database plan before relying on this app for long-term storage.

## Run locally with Node.js 20+
1. Create a PostgreSQL database.
2. Set \`DATABASE_URL\` to its connection string and \`JWT_SECRET\` to a random string of at least 32 characters.
3. Run \`npm install\`, then \`npm start\`.
4. Open \`http://localhost:3000\`.

Environment variables:
- \`PORT\` — web port (Render supplies this automatically)
- \`DATABASE_URL\` — PostgreSQL connection string
- \`JWT_SECRET\` — secret used to sign seven-day access tokens
- \`NODE_ENV=production\` enables TLS for the database connection (Render provides it automatically)

## Notes
Passwords are bcrypt-hashed. Authenticated API routes require a signed token. Chat is allowed only after a friend request is accepted. The current implementation supports direct text messages; it is not end-to-end encrypted and should not be used for sensitive communications.
